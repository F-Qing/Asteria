## 0. 三个必须先知道的结论

### 0.1 ⚠️ `mvn test` 现在是红的（与改动无关）

`asteria-server/src/test/java/com/asteria/server/Text.java:22` 硬编码了你本机的绝对路径：

```java
Path.of("D:\\FinalText\\题库脚本源码\\1.8.0\\学习通题库_20260906_000106.txt")
```

- **在你的机器上**：能跑通（文件存在），但它**没有任何断言**，跑通也没有校验意义
- **在任何别的机器/CI 上**：这个文件不存在 → `NoSuchFileException` → **测试直接失败**

**后果**：现在**无法用"测试全绿"作为改造的验收基线**。所以阶段 0 的第一件事就是删掉它，让测试基线先变绿，后面每一步才有得比。

### 0.2 ⚠️ shell 被沙箱拒绝，我无法编译

默认 `workspace-write` 授权路径报 `SetNamedSecurityInfoW failed (Win32 5)`，连只读命令都在授权阶段失败；走一次性提权（`danger-full-access` + 理由）可以执行。

**在拿到 0.3 的选择前，不建议开始写代码——写了也验证不了。**

### 0.3 需要你选：shell 权限怎么处理

| 选项 | 做法 | 代价 |

| **A** | 接受每次 shell 操作弹一次授权确认 | 最省事，但每批改动都要你点一下 |

## 1. 阶段总览

```
阶段 0 · 死代码清理 + 文档纠偏          ← 零风险，且能修复测试基线
   │
   ├─ 阶段 1 · 分层与命名规整             ← 纯结构调整，行为不变
   │
   ├─ 阶段 2 · 统一契约与错误处理          ← 改接口语义，需前后端一起回归
   │
   ├─ 阶段 3 · 并发与任务生命周期          ← 风险最高，收益最大
   │
   ├─ 阶段 4 · 性能与数据一致性            ← 需要真实数据量才能验证收益
   │
   └─ 阶段 5 · 工程化与安全（可随时插入，其中鉴权优先级取决于项目定位）
```

**排序理由**：0 不改行为且能修好测试基线；1 只动结构、可独立验收；2 会动接口契约，必须在 3/4 之前定死（否则回归两次）；3 风险最高，放在契约稳定之后；4 的收益需要数据量才能量化；5 可随时插入。
