# 解析器测试语料（parser-data）

这三份是**真实题库文件**，用来做解析器的回归与压测语料，不是构造的样例。

| 文件 | 来源 | 题数 | 有选项 | 无选项 | 有答案 |
|---|---|---:|---:|---:|---:|
| `学习通题库_50题.txt` | 学习通导出（HTML 课程） | **50** | 50 | 0 | 50 |
| `教材习题_POI抽取_302题.txt` | 教材 Word 用 `DocxTextReader`（POI）抽出的纯文本 | **302** | 144 | 158 | 0 |
| `去重合集_350题.txt` | 上面两份按「题干+选项+答案」去重后合并 | **350** | 194 | 156 | 50 |

## 怎么用

```java
// 从 classpath 读，测试里直接拿
String text = new String(getClass().getResourceAsStream("/parser-data/学习通题库_50题.txt")
        .readAllBytes(), StandardCharsets.UTF_8);
List<RawQuestion> list = new QuestionParser().parse(text);
```

或者手动验证：把任一文件按「题目格式要求」上传到系统，看解析出的题数是否与上表一致。

## 三份文件各自守什么

| 文件 | 守什么 |
|---|---|
| 学习通 50 题 | **标准格式**的正向基线：`【第 N 题】` + `题目：` + `选项：` + `我的答案/正确答案` |
| 教材 302 题 | **教材式写法**：`习 题 N` 分章、`（1）` 题号、选项挤在一行、**整份没有答案**（要靠 AI 补） |
| 去重 350 题 | 合并后的**大体量语料**，用于并发压测与回归（单次导入 350 题足够看出并发差异） |

## 两个必须知道的数字问题

1. **教材这份抽出 302 题，而旧文档里记的是 295 题（单选 144 + 简答 151）。**
   - 单选 144 与旧记录一致，差在简答（158 vs 151）。
   - 用**改动前**的解析器（commit `4394962`）复跑同一份文本，结果同样是 302 ——
     **说明差异不是解析器改动造成的**，极可能是当初统计用的 Word 和这份不是同一版。
   - 所以断言请以 **302** 为准；简历上若写 295，建议按真实文件再核一次。

2. **去重不能用「题干」做指纹。**
   教材里的编程题题干全是 `下列代码的输出结果是哪一项？`，真正的区别在**选项**里。
   按题干去重会误删 **13 道不同的题**。正确指纹是 `题干 + 选项（字母+文本）+ 答案`。

## 去重规则（生成 `去重合集` 时用的）

```java
// 归一化：去掉所有空白与常见标点，转小写
String norm(String s) { ... }

String fingerprint(RawQuestion q) {
    return norm(q.getRawStem()) + "||"
         + options.stream().map(o -> o.getKey() + "=" + norm(o.getText())).collect(joining(";"))
         + "||" + norm(q.getRawAnswer());
}
```

原始文件（`项目复习手册/uploads`）里的 9 个文件按 MD5 只有 **2 份不同内容**：
7 个 txt 完全相同、2 个 docx 完全相同 —— 所以只需要这两份语料。
